# 詳細ルール（v0.2 案）— docs/ai/詳細ルール.md に置く想定

AGENTS.md（核）から分けた詳細です。常時読み込みの対象ではないので、関係する作業の前に参照してください。
根拠：2026-11-15 の壁打ちで決めた複数 AI 開発の運用メモと、Gemini への確認回答（15問＋追加3問）。Gemini の回答は自己申告で、公式ドキュメントでの独立検証は未実施。

## 1. Gemini（Antigravity / VS Code）を使う前の準備

- PC 側で `git` と `gh auth login` を済ませておくこと。PR 作成はターミナルから git / gh CLI を呼ぶ方式
- **Settings の Account →「Enable telemetry」をオフにすること。** 個人プランのデフォルトのままだと、送ったコードがモデル改善に使われたり、人間のレビュアーに見られたりする可能性がある
- **仕事関連のコードや情報は個人の Gemini に渡さない。** 個人開発専用とする（消費者向け規約で、法人向けのデータ保護保証がないため）
- PR レビューの投稿は、最初はローカル Markdown に出力して洋平さん／ムーが確認してから投稿する

## 2. モデルの目安（固定しない）

- 設計など推論が要る役：Gemini Argon、Claude Opus
- 量のある実装：Gemini Hydrogen など高速なもの
- あくまで配分の目安。役割そのものはモデルに固定しない
- モデル事情の変化の例：Claude の Fable は期間限定で、2026-11-17 から Opus に変わる

## 3. 切り替えのきっかけと手順

| きっかけ | 切り替え方 |
|---|---|
| Claude のトークンが切れた | ムーが状態を引き継ぎ文書にまとめる → Gemini が同じブランチ／Issue の続きを担当する |
| 作業が並行して増えた | Issue 単位で担当を分ける。同じブランチは同時に触らない |
| 実装が終わった | レビューは実装者でない側の AI（またはムー）が担う |
| 判断の重い作業が来た | SE・レビューには Claude を温存し、量のある実装を Gemini に寄せるなど、ムーが配分を組み替える |

## 4. バトンタッチ時の指示文の型

- Claude Code → Antigravity（PC 側）：
  「git fetch して <ブランチ名> をチェックアウト（または Worktree で開いて）、docs/handovers/<ブランチ名>.md を読んで。残タスクを進めたあと、Built-in browser で画面表示とコンソールエラーがないか確認して PR を作成して。」
- Antigravity → Claude Code（クラウド側）：
  「docs/handovers/<ブランチ名>.md と直近のコミット差分を確認して。現在の実装に対するコードレビューとエッジケースのユニットテスト追加を行い、完了したら引き継ぎ文書を更新して push して。」

## 5. コーディング規約の置き場所

- 詳細なコーディング規約は、AGENTS.md ではなく `.agents/rules/` に条件付き読み込み（対象パスの glob 指定）で分ける
- v0.2 セットには例として2ファイルを用意した（rules-react-components.md、rules-testing.md）。Gemini のスリム版テンプレートの例をもとに、このリポジトリの実態（React 18、useReducer 中心、Tailwind なし、外部 API なし）に合わせて調整済み
- 中身はこのリポジトリの実態に合わせて書く（React 18、useReducer 中心、ドメインロジックは src/domain/ 等）。汎用テンプレートの具体値をそのまま持ち込まない
- コミットメッセージの形式は、このリポジトリの既存の運用（日本語の説明形式）を変えない
- 配置メモ：`docs/handovers/` には空ディレクトリ保持のため `.gitkeep` を置く
