# CLAUDE.md のレビューと修正の記録（2026-11-03）

CLAUDE.md の初版を、観点を変えて3回レビューし、指摘を反映した記録。各回のレビューは、初版を書いた実装担当とは別のレビュー役（サブエージェント）が行い、ファイルは編集せずに指摘だけを返した。修正は実装担当が行い、回ごとに1つのコミットにしている。

| 回 | 観点 | 指摘の数 | 修正のコミット |
| --- | --- | --- | --- |
| 1 | 企画書との整合と曖昧さ（企画書を歪めていないか、GTDの理解、推測で進めそうな点） | 高4・中6・低6 | 「レビュー1回目（企画書との整合）の指摘を反映」 |
| 2 | 実装できるか（データのルール、明確化の出口、日時、保存の容量、セキュリティ、フック） | 高7・中10・低4 | 「レビュー2回目（実装できるか・データのルール・セキュリティ）の指摘を反映」 |
| 3 | UX・運用・全体の一貫性（手順の複雑さ、1週間の運用、章の参照、用語、サブエージェントの分担） | 高4・中9・低7 | 「レビュー3回目（UX・運用・全体の一貫性）の指摘を反映」 |

## 1回目：企画書との整合と曖昧さ

| 主な指摘 | 修正 |
| --- | --- |
| 明確化の4つの判断を企画書の並びのまま直列に問うと、複数ステップのものの最初の一手を委任・2分で扱えない。参照資料の判断フローでは、次の一手を決めた後の出口は並列 | 6.1を「行動 → 複数ステップ → 次の一手を書いて選ぶ」の3段に変え、発注者への質問にした（付録A15） |
| 「主要プロジェクト＝四半期に置いたプロジェクト」は、GTDのプロジェクトの粒度と、四半期シートの「終わらせる」・年間表の「進める」の違いを扱っていない | 四半期に置くのは任意、またがるものは終わらせる予定の四半期に置く、とした（5.1、A16） |
| 単独のアクションがテーマと結びつかない | 任意でテーマを持てる案にした（A17） |
| 企画書1章の「年→四半期→月→週→日」と4章のスコープが食い違うのに、CLAUDE.mdが「企画書に無い」と断定していた | 企画書の中の食い違いとして質問にした（4.2、A18） |
| 後回し、次の一手を書き直す工程、移動の日時、やらないことの空欄、G7の基準、期間の出典、章番号のずれ、用語の揺れ | それぞれ反映し、用語集（付録B）を追加した |

## 2回目：実装できるか

| 主な指摘 | 修正 |
| --- | --- |
| 明確化の出口ごとに、作られる要素・消える要素・必須の入力が定まっていない | 6.4に出口の表を置き、1つの関数で全部作るか何も作らないかにした |
| 既存のプロジェクトに次の一手を足す道が無く、G3を日々の運用で満たせない | 明確化で既存のプロジェクトを選べ、プロジェクトの画面から直接足せる案にした（A23） |
| 移動の組み合わせ、idの引き継ぎ、完了したプロジェクトの子の扱いが無い | idは種類を通じて一意で移動で変わらない、完了したものは移せない、完了したプロジェクトに未完了の子を残さない、とし、移動の表を設計案の必須項目にした |
| 日時の保存形式とタイムゾーン（CIはUTC） | UTCのISO 8601で保存し、判定は端末のタイムゾーンで行い、テストは `Asia/Tokyo` に固定する（5.2） |
| localStorageの容量（同じオリジンで約5M文字）と読み込みの上限の食い違い | 上限・容量の見込みを設計案で決め、書き出したJSONを必ず読めることをテストする（8.2） |
| 同一オリジンのリスクの書き方が足りない | 全PRプレビューが載ること、XSSが1つあれば漏れること、軽減策と代わりの案を8.3に書いた |
| 節目2に作業が偏り、途中でスキーマを上げることになる | 節目2で全エンティティを含むスキーマv1を確定し、移動は節目3へ回した |
| フックが jq の無いときに通ってしまい、`npx` が未インストールのパッケージを取ってくる | jq が無ければ拒否し、`npx --no-install` に限った |

## 3回目：UX・運用・全体の一貫性

| 主な指摘 | 修正 |
| --- | --- |
| プロジェクトを作る明確化で「やった」を保留する仕様が複雑 | 最初の一手を「後でやる／任せる」の2択にし、補足で案内する（6.1、A24） |
| 連絡待ちで作ったプロジェクトが「次のアクション 0件」と出て、止まっているものと区別できない | 次のアクションと連絡待ちの件数を並べて出す（4.3・7.2） |

| 12章の未決を1件ずつ承認する手間 | 12章を「節目1の前」「設計案と一緒」に分け、一括で承認できる形で尋ねることにした |
| 確認ダイアログの方針がばらばら | 日常の操作は「元に戻す」で救い、確認は取り消せない重い操作だけにする方針を7.1に書いた |
| 新しいセッションが企画書の在りかを知らない、サブエージェントの観点が古い・分担があいまい | 冒頭に要点と企画書の在りかを置き、各サブエージェントの観点と13章の分担を更新した |
