## UXの方針との対応（CLAUDE.md 7.1）
- マニュアル無しで分かる：明確化の各質問に短い補足を常に出す。入力欄の見出しに「必須」「任意」を文字で付けた（発注者の要望）
- 手順を複雑にしない：明確化は3つの質問。前の質問に戻っても入力は消えない。確定するまでデータは変わらない
- 確認ダイアログは、JSONの読み込みと保存データの消去だけ。明確化・完了・削除は、確認を出さずに直後の「元に戻す」で救う（D1）
- PCとスマホ：スマホは下部のタブバー、上部に固定するのは収集の入力欄の1行だけ。スマホの「戻る」は明確化の前の質問に戻る（D14）。プロジェクトの一覧はスマホではカードの並び。Playwright で PC 1280px とスマホ幅のどちらも横スクロールが出ないことを確かめた
- 色だけで伝えない：完了は「✓完了」、必須は「必須」の文字でも示す
- キーボード：画面の切替・質問の切替・確定の後は、見出しにフォーカスを移す

## 予定から変わったことと、その理由
- **日程**：計画では節目2の完了を 11/26 としていたが、実装は 11/5 に終わった。発注者の操作確認（計画の 11/23〜11/24）は前倒しで行える
- **ホームを節目2に入れた**（計画 2章のとおり）：アプリを開いたときに出す画面が要るため、件数だけの最小限のものを PR 3 で作った。プロジェクトの表と今の四半期は節目3
- **プロジェクトの一覧と詳細を一部前倒し**（計画どおり PR 5）：明確化で作ったプロジェクトを見て、子を完了にできるところまで
- **PR 2b**：表示の切替（ライト・ダーク）の保存は最小限にし、PRプレビューの帯（実データを入れないよう知らせる）を前倒しで入れた
- **明確化の URL**：質問ごとに URL（`#/inbox/clarify`・`/2`・`/3`）を持たせ、確定とやめるでは途中の履歴を戻すことにした（スマホの「戻る」で前の項目の質問に戻らないように。設計案 2.1）
- **置く四半期の選択肢**：明確化では今の年度と次の年度の8つに限った（それ以外は節目3のプロジェクトの画面で直す。設計案 3.5）
- **時刻の揃え方**：完了・編集の時刻は、今の時刻と更新日時の遅い方にした（時計の遅れた端末でも日時の順序の検証に引っかからないように。D15 と同じ考え方）
- **入力欄の「必須」「任意」の印**：発注者の要望で PR 5 に足した
