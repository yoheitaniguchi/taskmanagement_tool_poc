## 2. 設計上の決定事項・前提

- **「先頭」は配列の順の先頭**（`state.actions` の順で、そのプロジェクトの最初の未着手のアクション）。作成日時では並べない。いつか・多分や連絡待ちから移したものは、作成日時が古くても配列の末尾に入るため（計画 2.6 で決定）。改善提案 Q4 の「いちばん古い」とは違うので注意
- **列の名前は「次のアクション（先頭）」**（計画 7.1 の7）。連絡待ちだけのプロジェクトは「—」になる。ツールが一手を選んだように読まれないよう、何を出しているかが分かる名前にした
- **件数・日付で何かを判定しない、強調しない**（記録 4.3）。0件の枠も他と同じ見た目
- **`quarterShortLabel(placement, now)`**（`src/domain/fiscal.ts`）：ホームの表だけで使う。置いていない →「置いていない」、今の年度 →「第N四半期」、それ以外 →「YYYY年度 第N四半期」。年度の判定は端末のタイムゾーンで行う（`Asia/Tokyo` の境界のテストあり）。プロジェクトの一覧・詳細は、年度と暦の月の両方が分かる今の表記のまま
- **計画・改善提案から変えたこと**（自己点検の指摘による。洋平さんの確認待ち）
  1. 「次のアクション（先頭）」の列を、次のアクションの件数のすぐ後ろに置いた（列の並び：…置いた四半期、次のアクション、次のアクション（先頭）、連絡待ち）。「—」が「次のアクションが0件」の意味だと読めるように
  2. スマホのホームのカードを、改善提案 3.2 の「2行」ではなく3行にした（1行目：名称、2行目：テーマ・四半期・次のアクションと連絡待ちの件数、3行目：次のアクション（先頭））。先頭の内容まで2行目に入れると、幅412pxで折り返して読みにくくなるため
  3. `quarterShortLabel` で、置いていないときは関数が「置いていない」を返す（計画 2.6 では「PR で決める」としていた）。スマホのカードでは「四半期に置いていない」と出す
  4. 置き場の枠の見出しをリンクの色にした（押せると分かるように）
