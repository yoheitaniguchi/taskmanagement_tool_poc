# セキュリティレビュー チェックリスト

`security-reviewer`エージェント・`/security-review`スラッシュコマンドが参照する正本。
既存PoC（`project_management_poc`）のチェックリストを、このPoCの前提に合わせて書き換えたもの。
観点のもとは CLAUDE.md 5.3（データの守るべきルール）・8.2〜8.4。未構築の項目は「該当なし（未構築）」とする。

`security-reviewer`は各項目について、該当箇所がある場合は「ファイル:行」「根拠」「重大度
（Critical/High/Medium/Low/Info）」を、該当なしの場合は「該当なし＋理由」を記録すること。
重大度は「実際に悪用可能で影響が大きい＝High以上、到達不能・理論上のみ＝Low」を基準とし、
断定できない場合は根拠と不確実性を併記して**推測で重大度を上げない**こと。

## 前提（このリポジトリの実態）

- **バックエンドを持たない1ページのアプリ**（React + TypeScript + Vite）。認証・セッション・DBは無い。利用者は発注者1名
- **リポジトリとGitHub Pagesのサイトは公開されている**。実データ（タスク・目標・メモ、書き出したJSON）は**健康・家計・人間関係などの私的な内容を含む**。利用者のブラウザ（localStorage）とPCにだけ置き、リポジトリにもビルド成果物にも含めない
- localStorageのオリジン `yoheitaniguchi.github.io` は、既存PoCなど同じアカウントの他のアプリと共有している（リスクの受け入れは CLAUDE.md 12章で発注者が決める）
- GitHub Pages では応答のヘッダーを付けられず、metaタグのCSPでは `frame-ancestors` が効かないため、ほかのサイトの枠（iframe）の中に表示されるのを止められない。主要なブラウザは、ほかのサイトの枠の中の保存データを分けて持つため、実データには届かない。発注者が受け入れた（2026-11-05。`docs/security/reports/review-20261105-0337.md` の SEC-003）。新しい指摘にしない
- 外部サービスとは通信しない。カレンダーとの連携もしない（CLAUDE.md 4.2）
- 外部入力は、利用者が入力する文字と、読み込むファイル（保存したJSON。別の端末で書き出したものを含む）と、起動時に読むlocalStorageの値だけ
- PCとスマホの両方で使い、端末の間はJSONの書き出し・読み込みで手で受け渡す（CLAUDE.md 8.5）。受け渡しには個人のクラウドストレージの、共有設定をしない専用のフォルダを使い、読み込んだ後の古いファイルは消す（CLAUDE.md 12.3）。アプリ自体はクラウドと通信しない

## A. 公開リポジトリと実データ

- 実データがコード・テスト素材・ドキュメント・**コミット履歴**・ビルド成果物（`dist/`）・PRの本文・スクリーンショットに含まれていない
- テスト用のデータは架空のもので、決められた置き場所（`src/**/__fixtures__/` またはテストのコード内）にだけある。実在の人名や、具体的な健康状態・金額など、実データらしい内容を書いていない
- `.gitignore`で、アプリが書き出すファイル（接頭辞 `tmpoc-`）と `.env*`（`.env.example`を除く）を除外している。CIで置き場所以外の`*.json`の追加を検査している（設定ファイルを除く）
- 節目の資料・振り返りに、実データ（個別のアクションやプロジェクトの内容など）を載せていない。載せるのは件数などの集計と、発注者が公開してよいと判断した内容だけ
- 秘密情報（トークン・パスワード等）がコード・設定・履歴に無い（`gitleaks`）。秘密情報を扱うコードが現れたこと自体を指摘する
- 手順書（`docs/weekly-review.md`）の受け渡しの手順が、12.3で決めた経路・置き場所と一致し、共有の設定をしたフォルダや公開の場所を案内していない

## B. 外部通信

- アプリが外部へ通信していない（`fetch`・`XMLHttpRequest`・`WebSocket`・外部のスクリプト・フォント・画像・解析タグ）
- 本番ビルドの`index.html`にCSP（`default-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'self'; form-action 'none'`）があり、開発時だけの例外が本番に漏れていない
- カレンダーへの登録を促す表示が、外部サービスへのリンクや通信になっていない（文言の表示だけ）

## C. 入力の検証と出力の無害化

### 読み込むデータ（JSONファイル・localStorage）
- 検証関数は`unknown`を受けて型ガードで絞っている（`any`や`as`で検証をすり抜けていない）
- ファイルサイズ・配列の件数・文字列の長さに上限がある
- IDが一意で、参照先（project）が存在する
- 日付・日時の形式、年度・四半期の範囲、列挙値（テーマID・状態）を許可リストで判定している
- `__proto__`・`constructor`・`prototype`のキーを拒否している。パース結果をスプレッドや`Object.assign`で状態にマージせず、検証済みのフィールドだけを詰め替えている。ID辞書は`Map`か`Object.create(null)`
- 検証に失敗したら一部も取り込まず、現在の状態を変えない。エラーは利用者向けの日本語で、生の例外文言を出さない
- スキーマの版を確認し、版ごとの移行のあとに検証している。未来の版は拒否する

### 画面表示
- `dangerouslySetInnerHTML`を使っていない（ESLintで禁止している）
- 自由記述（収集した内容・メモ・資料の本文・プロジェクトの成果・やらないこと）はテキストとしてだけ表示し、URLとして`href`に渡していない（渡す場合は`http(s)`だけに限っている）

## D. データの完全性（CLAUDE.md 5.3）

- 5.3のルールを`src/domain/`のドメイン関数で守らせ、そのテストがある。reducerのaction・JSONの読み込みで迂回できない
  - 収集箱の項目を作る経路が収集だけで、ほかの要素を収集箱に戻す経路が無い
  - テーマは7件固定。年次目標は年度 × テーマ、四半期シートは年度 × 四半期で一意。重点テーマは最大3つで重複しない
  - 参照（projectId）が存在するプロジェクトを指す。状態と完了日時が整合している
- 取り消せない操作（削除、JSONの読み込み、保存データの消去）に確認か「元に戻す」がある

## E. ブラウザの保存（localStorage）

- キーに名前空間（`taskmanagement_tool_poc:`）がある。PRプレビューは別の名前空間（`taskmanagement_tool_poc-pr-preview-<番号>:`）で、本番の保存データを読み書きしない
- 起動時の読込も読み込み検証と同じ関数に通し、失敗したら自動保存を止めて元の値を退避している（空の状態で上書きしない）
- 書き込みの失敗（容量超過など）を消えない表示で利用者に知らせ、JSONの書き出しを促している
- 端末名は、使える文字を許可リストで絞ってから、書き出すファイル名とJSONに入れている（パスの区切りや制御文字を入れない）。読み込んだJSONの端末名も、表示の前に同じ検証に通している
- 複数のタブで開いたときに、他のタブの更新を黙って上書きしない（`storage`イベントで検知して読み取り専用にする等）
- 保存データを消去する操作がある。Cookie等、他のサイトと共有される前提の保存をしていない

## F. CI・依存関係（CLAUDE.md 8.4）

- CIでlint・型チェック・単体テスト・`@security`テスト・依存の脆弱性スキャン・gitleaks・ビルドを実行している。ビルド成果物にデータファイルが無いことを検査している
- 各ワークフローのトップレベルが`permissions: contents: read`。`contents: write`（`gh-pages`への配信）・`pull-requests: write`（PRプレビューのURLのコメント）は配信のジョブだけ
- 配信のジョブは`npm`を実行せず、書き込み権限の無いジョブで作ったビルド成果物を受け取るだけ。`actions/checkout`は`persist-credentials: false`
- PRプレビューは、このリポジトリのブランチからのPRだけを対象にする。Dependabot のPRは対象外
- 配信はCIの成功を条件にしている。`concurrency`がある
- トリガーに`pull_request_target`を使っていない
- Actionはコミットsha固定。Dependabot（npm・github-actions）がある
- `package-lock.json`をコミットし、CIは`npm ci`。本番依存はhigh/critical 0件。dev依存の結果とライセンス一覧を確認している
- `vite.config.ts`で開発サーバーを外部に公開していない（`server.host`）

## 人手で確認する項目（テスト不能）

- GitHub PagesのSourceが`gh-pages`ブランチになっている（`gh-pages`へ書き込むのは`main`の配信とPRプレビューのワークフローだけ）
- `main`のRulesetでCIの成功が必須になっている
- 同一オリジンを共有する他のアプリ（既存PoCなど）の存在と、そのリスクの受け入れが CLAUDE.md 12章に記録されている

## レビュー結果の記録形式

`docs/security/reports/review-YYYYMMDD-HHMM.md`に、以下を出力する。

- サマリ：検査範囲、コミットSHA、重大度別の件数
- 指摘一覧（各指摘に必須の項目）：
  - ID（`SEC-001`）、重大度（Critical/High/Medium/Low/Info）、カテゴリ（本書のA〜F）
  - 該当箇所（`ファイル:行`）、根拠、影響、修正案
  - 対応するテスト（追加したテストファイル名とテスト名）または「テスト不能の理由」
- 該当なしとした項目と、その理由
- テスト実行結果（成功/失敗数、失敗の内訳）
- 秘密情報らしき値・実データは書き写さない（ファイル:行と種類だけを書く）
