### 2.1 全部のPRに共通すること

- **保存したデータを読めなくしない**：PR 2b 以降、本番のブラウザには実データが入っている。節目3では `validateState` を厳しくしない（変えるなら緩める方向だけ）。スキーマは v1 のまま変えない。手で作った架空のv1のデータ（`src/domain/__fixtures__/export-v1.json`）に加えて、節目2のドメイン関数（収集・明確化・編集・完了）を実際に呼んで作った架空の状態も、書き出して読み込めることを回帰テストで確かめる（PR 6 で足す）
- **新しいドメイン関数**は、結果が `validateState` を通ることと、時計のずれ（今の時刻が更新日時より前）のテストを付ける。置き場ごとの件数の上限（10,000件）は、`clarify.ts` にある確認を共通の関数にして、新しい関数でも使う（上限を超えたら理由を出して失敗にする。黙って捨てない）
- **知らない値**（出口・置き場の種類・`childPolicy`・読めない時刻）を受け取ったら、例外ではなく失敗（`fail`）を返す（SEC-006 の修正案）。既存の `clarify.ts`・`items.ts`・`reducer.ts` を揃えるのは、動作を変えない別のコミットとして PR 6 に入れる（差分を読み分けられるように）
- **プロジェクトの完了での子の日時**：子の完了日時は、設計案 4.4 のとおりプロジェクトの完了日時と子の作成日時の遅い方にし、子の更新日時はその完了日時と子の更新日時の遅い方にする（「完了日時 ≦ 更新日時」が時計の遅れた端末でも破れないように。設計案 4.4 に書き足す）
- **「元に戻す」の文言の件数**（「プロジェクトと、未完了の N件を完了にしました」）は、reducer で前後の状態から数える（ドメイン関数の戻り値の形は変えない）

### 2.2 プロジェクトの詳細から四半期シートへ

年度の切替はURLに持たない（設計案 2.1）。そのため、プロジェクトの詳細の「つながり」のリンクから開くときだけ、置いた年度を画面に渡して、その年度の四半期シートを開く（URLには持たない。再読み込みすると今の年度に戻る）。

### 2.3 ドラッグで受け取る値（設計案 3.8・CLAUDE.md 7.2）

- カードが入れるのは、このアプリの種類（`application/x-tmpoc-project`）のプロジェクトの id だけ。`text/plain` や名称は入れない（ほかのアプリへ落とされたときに内容が漏れないように）
- 受け取るのは、その種類の値だけ。存在するプロジェクトの id かを確かめる。移す先の年度・四半期は、落としたセルから取る（受け取った値からは取らない）
- `placeProject` は、テーマを変えないことを自分でも確かめる（画面から渡されたテーマがプロジェクトのテーマと違えば失敗）。年度の範囲外と知らない id も失敗にする
- これらを `@security` のテストで確かめる。PR 9 はマージの前に `security-reviewer` で差分を点検する（外から値を受け取る、節目3で唯一の新しい経路のため）

### 2.4 画面の確かめ方のための架空のデータ

PRプレビューは空のデータで始まり、実データは入れない（8.3）。ロードマップ（G5）を確かめるために、架空のデータのJSON（1つのセルに5枚、名称が2行になるもの、四半期に置いていないもの、前の年度に置いた進行中のもの、完了したもの）を `src/domain/__fixtures__/` に置き、テストでも使う。発注者はこれをPRプレビューで読み込んで確かめる（D20。読み込み方はPRに書く）。
