## 指摘一覧

### SEC-006　Info　D（データの完全性）
- **該当箇所**：`src/domain/clarify.ts`（`place` の switch に default が無い）、`src/domain/items.ts`（`deleteItem` の `LIST_KEY[ref.kind]`）、`src/domain/reducer.ts`（`new Date(action.at)`）
- **根拠**：action の値が型の外にあると、reducer の中で例外になり、「何もしない」にならない（知らない出口・知らない置き場の種類・読めない時刻）
- **影響**：検証を迂回する経路にはならない（`applyResult` は `validateState` を通った結果だけを反映する）。action を作るのは `src/App.tsx` の型付きのコードだけで、URL・storage イベント・ファイルの読み込みからは作れない。到達しない理論上の問題で、起きても ErrorBoundary の画面になるだけで、保存データは変わらない
- **修正案**：任意。知らない値なら `fail(...)` を返す、読めない時刻なら何もしない。今は直さない
- **対応するテスト**：無し（型の外の action は、今のコードからは作れないため。Info なので `/security-review` の手順でもテストの対象外）

## 該当なしとした項目と理由

- **A 公開リポジトリと実データ**：データファイル（`*.json`・`*.csv`・`.env*`・`tmpoc-*`）の追加は無い。テストの文字列は架空のもの（「テスト用の項目1」「テスト相手」など）。秘密情報を扱うコードは増えていない
- **B 外部通信**：追加したコードに `fetch`・XHR・WebSocket・`sendBeacon`・`window.open`・外部 URL は無い（ESLint でも禁止、lint 0件）。CSS に `url(`・`@import`・`@font-face` は無い。カレンダーの出口は項目を消すだけ
- **C 入力と表示**
  - URL：`parseRoute` は決まったパスだけを受け付け、読めない値・知らない値はホームにする。プロジェクトの id は UUID の形だけ。URL から操作は起きない
  - 履歴の操作（`src/state/navigate.ts`）：受け取る hash はコードの中の決まった値だけで、ほかのサイトへ飛ぶ道は無い。戻る先が無いときに `popstate` の待ち受けが残りうるが、戻る数は明確化の中で積んだ数を超えないので、ふだんは起きない（UX の頑健さの話）
  - 表示：利用者の文字はすべて JSX のテキストか属性として出す。`dangerouslySetInnerHTML` は無い。資料の本文はリンクにしない。ブラウザのタブの名前は画面の名前だけ（@security のテストあり）
  - 入力欄：`readField`・`captureTextError` で、上限・改行・制御文字を確かめてから保存する
- **D データの完全性（5.3）**
  - 新しい action（capture・clarify・clarifyBulk・editItem・completeItem・uncompleteItem・deleteItem）は、どれも `applyResult` → `validateState` を通る。状態を外から置けるのは、今も `replaceState`（検証し直す）と `reset` だけ。id が足りなければ検証で落ちる（テストあり）
  - 「元に戻す」は、前に検証を通った状態にだけ戻し、今の状態が直後の状態と同じときだけ働く。読み込み・消去・別のタブの変更で捨てる。保存しない
  - 収集箱に項目を足すのは `capture` だけで、戻るのは「元に戻す」だけ
  - 完了したプロジェクトに未完了の子を残さない：明確化（進行中のプロジェクトだけ）・編集の付け替え（同じ）・完了の取り消し（親が完了なら断る）・読み込みの検証の4か所で守り、テストがある
  - テーマを持てるのは単独のアクションだけ（明確化・編集・検証）。状態と完了日時が整合し、端末の時計が遅れていても日時の順序が逆にならない（テストあり）
- **E ブラウザの保存**：追加したコードで localStorage などに触るところは無い（`persistence.ts` だけ）。起動時に読めなかったデータがある間は、収集・明確化・変更を止め、自動保存も止まったまま
- **F CI・依存関係**：この差分で変わっていない
- **範囲外・未確認**：リポジトリの設定（Pages の配信元、`main` のルール）は前回と同じく人手で確認する項目。SEC-003 は受け入れ済み
