## 指摘一覧

### SEC-010　Info　E（ブラウザの保存）・B（外部通信）
- **該当箇所**：`eslint.config.js` の `REFLECT`・`noDynamicGlobalAccess`（S-3 で足した禁止）
- **根拠**：`eslint --stdin` で確かめたところ、次の形が止まらなかった。`window.Reflect.get(navigator, "storage")`・`globalThis.Reflect`（`REFLECT` は識別子として直接書いた `Reflect` しか見ない）、`(window as unknown as Record<string, unknown>)[k]`・`window![k]`（型の変換で包むとセレクタから外れる。TypeScript では string のキーで書くと型エラーになるので、型の変換はむしろ自然に書く形）、`window.navigator[k]`、`(0, window)[k]`、`Object.entries(window)`。設計 6.1 とテストの「止まらない例」には、別名・`Object.getOwnPropertyDescriptor`・`window.window[k]` の3つしか書いていなかった。今の `src/`（テストを除く）に、どの形も無い
- **影響**：理論上だけ。通信は本番の CSP（`connect-src 'none'`）でも止まる。保存の API を `persistence.ts` の外で使えると、データのルールの入口が1か所でなくなる、という設計上の守りが弱まるだけ
- **修正案**：`no-restricted-properties` に `Reflect` を足す。セレクタを、型の変換の中身（`object.expression`・2重の `as`）と1段下の参照（`object.object`）も見るように広げる。直さない形は、テストの「止まらない例」と設計 6.1 の限界に足す
- **対応**：**対応済み**（この PR。計画 9章の4「禁止を足すだけ」の承認の範囲）。`window.Reflect`・`globalThis.Reflect`・`(window as X)[k]`・2重の `as`・`window![k]`・`window.navigator[k]`・`window.window[k]` が止まる。`(0, window)[k]` と `Object.entries(window)` は「止まらない例」に足し、設計 6.1 の限界の一覧を直した
- **対応するテスト**：`security/eslint-rules.security.test.ts`（`[@security] … は、どのファイルでもエラーになる（SEC-009）` に7件、`… は、構文の検査では止まらない（限界の記録。SEC-009）` に2件を足した）。Info だが、禁止を足したので回帰のテストを付けた

## 見てほしいとした点の確認結果

- **S-1（依存）**：lockfile の取得元はすべて `registry.npmjs.org`。新しく入った包みは開発用だけ（minimatch が使う `@isaacs/nonrecursive-glob-match`、rolldown の wasm32 の予備。予備は optional で、Linux x64 の CI では入らない）
- **S-2（枠の中）**：`src/main.tsx` は `isFramed(window)` を最初に判定し、枠の中なら `textContent` で文言を置くだけで、保存データを読む処理（`applyTheme(readThemePreference())`）も描画（`createRoot`）も呼ばない。読み込むモジュールに、読み込んだ時点で保存データを読む処理は無い。例外のときは「枠の中」に倒す。`main.tsx` を通した結合はテストが無く、コードを読んだのと、実装担当がブラウザ（Chromium、iframe に入れた本番ビルド）で確かめた結果による
- **T-1（検証の迂回）**：無い。`operate` の結果が状態になる経路は、reducer の `applyResult`（失敗・同じ参照・`validateState` に通らない結果を捨てる）だけ。`App.tsx` の `run` は `operate` の結果を理由の文言にしか使わない。知らない操作は `never` の分岐で何もしない（SEC-006 を維持）。任意の状態を置ける操作は `replaceState`（検証あり）と `reset` だけのまま
- **Q-1（反映と保存）**：問題なし。読み取り専用のタブでは `commitAction` が反映しない（`@security` のテストあり）。別のタブの変更を知ったら、その場で読み取り専用にする（前は次の描画まで操作が通る隙があった）。消去の順番と自動保存の条件は変わっていない。注意：今後 `useTransition`・`useDeferredValue` を使うときは、描画のたびに読み取り専用の印を代入していることとの関係を見る（今の `src/` には無い）
- **Q-2（tsconfig）**：検査を足しただけで、緩めた項目は無い
- **CI**：`.github/` はこの範囲で変わっていない。提案（洋平さんの判断。CI の変更なので、この PR では変えない）：`npm audit` が0件になったので、`ci.yml` の開発依存を含む監査（今は `|| true` で表示だけ）を失敗扱いにするか

- **A 公開リポジトリと実データ・秘密情報**：範囲で足した・変えた JSON は `package*.json`・`tsconfig.json` だけ。計画・引き継ぎ文書・設計・コミットメッセージは手順と決定だけ。`.gitignore`（`tmpoc-*`・`.env*`）は効いている
